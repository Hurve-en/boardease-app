# Mobile application setup (BE-289)

This repository is the BoardEase tenant app. It already uses Expo SDK 58, React Native, TypeScript, and Expo Router. Native projects are generated by Expo; no separate React Native initialization is needed.

## File organization

| Location | Responsibility |
| --- | --- |
| `src/app/` | Route entry points and protected navigation layout. |
| `src/screens/auth/` | Login and registration screens. |
| `src/screens/HomeScreen.tsx` | Tenant home screen. |
| `src/components/auth/` | Auth-specific header and logo. |
| `src/components/ui/` | Reusable button and text field. |
| `src/lib/` | API authentication, token storage, and Supabase client. |
| `src/constants/theme.ts` | Shared app color palette. |
| `assets/` | App icons and splash assets. |
| `docs/images/` | Project diagrams and documentation images. |

Use PascalCase for screen/component filenames. Keep route filenames lowercase to preserve their URLs. Database schemas, migrations, and database tooling belong to the separate `boardingbills-web` backend repository.

## Run locally

1. Install Node.js 22 LTS or a newer supported LTS release, then run `npm ci`.
2. Copy `.env.example` to `.env` and fill in the environment values.
3. Start the Next.js backend separately.
4. Run `npm start` and open the app with an SDK 58-compatible Expo Go or development build. The computer and phone must be on the same network for a local backend.

Use `npm run android`, `npm run ios`, or `npm run web` to open a particular platform. The iOS simulator requires macOS. Cloud development builds can be created with EAS when needed.

## API configuration

`EXPO_PUBLIC_API_URL` is the backend origin without `/api`, for example `http://192.168.1.100:3000`. Replace the example IP with the computer running Next.js and make that server reachable on the local network.

A physical phone's `localhost` points to the phone, so use the computer's LAN IP. For the standard Android emulator, the host computer is available at `http://10.0.2.2:3000`. The iOS simulator and local web browser can use `http://localhost:3000`.

The existing auth connection in `src/lib/auth.ts` uses:

| Endpoint | Request | Expected response |
| --- | --- | --- |
| `POST /api/login` | `{ email, password }` | `{ accessToken, refreshToken, user: { role: "tenant" } }` |
| `POST /api/logout` | `{ accessToken, refreshToken }` | Local sign-out completes even when the backend is unreachable. |

The existing registration screen uses `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_KEY` directly. Set these to the Supabase project URL and public client key. Without them, login can still open and registration shows a configuration message on submission. Reload the app after changing environment values. The backend must allow the web app's origin when testing through a browser.

`EXPO_PUBLIC_` values are bundled into the client. Database credentials and Supabase service-role keys belong on the backend.

## Navigation

- `/` redirects signed-out users to `/login`.
- `/login` links to `/register`; registration links back to login.
- `/home` is protected by the stored-session check. Successful tenant login opens it.
- Logout clears local tokens and returns to login through the route guard.
- During session restoration, the app shows a loading indicator. A storage-read failure falls back to signed-out navigation.

Native token storage uses SecureStore; web uses AsyncStorage. The route guard checks local token presence. Backend authorization and token validity checks remain server responsibilities; automatic token refresh is not introduced by this setup task.

## Verification

Run these before submitting changes:

```sh
npm run lint
npm run typecheck
npx expo install --check
npx expo-doctor
npx expo export --platform all
```

Device smoke test with a running backend and test accounts:

- Cold start while signed out: login opens; registration opens and returns to login.
- Attempt to open `/home` while signed out: the protected screen is unavailable.
- Invalid credentials or unreachable backend: an error appears and submission becomes available again.
- Valid tenant credentials: Tenant Home opens; restarting the app restores access from stored tokens.
- Admin credentials: the mobile app rejects access.
- Logout: login opens, and back navigation cannot reopen Tenant Home. Repeat with the backend offline.

Automated checks do not replace this device test. See the saved project context for the latest verification results and remaining limitations.
